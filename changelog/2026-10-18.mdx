<Update label="October 18, 2026" description="TripAdvisor Reviews Scraper returns reviews again, Facebook Marketplace category URLs return their listings, and a run's automatic resumes last">

## Fixed

**TripAdvisor Reviews Scraper: reviews again**

Since October 2 TripAdvisor reads reviews through a new query, and every run ended with 0 results and no error, as if the URL were wrong. The scraper now sends the site's new query and reads its reviews. That query no longer returns `publish_platform` and `place_category`: the two fields stay in the results so integrations do not break, and are always empty. A query the site refuses now ends the run in error instead of "URL provided is invalid". See [TripAdvisor Reviews Scraper](/examples/tripadvisor-reviews-scraper/get-results).

**Facebook Marketplace Scraper: category URLs return their listings**

Facebook now serves category pages (`/marketplace/<city>/<category>/`) from its search, and they returned 0 listings; on the older category layout, the pages after the first did. Both return their listings again, page after page. See [Facebook Marketplace Scraper](/examples/facebook-marketplace-scraper/add-tasks).

**A run's automatic resumes last**

A run gets 3 automatic resumes after a pause on site or proxy failures. The workers of one run paused together counted 3 pauses within seconds, and the next worker ended the run in error. Pauses less than 5 minutes apart now count as one. And a scraper that keeps pausing itself on the same failures ends the run in error after 48 hours in a row, instead of pausing for days.

**Leboncoin Boutiques: a page Leboncoin answers with an error is asked again**

Leboncoin sometimes answers a boutiques directory with an error page in place of its stores; the task failed. It is now asked again through another exit.

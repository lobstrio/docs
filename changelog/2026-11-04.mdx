## Improved

**Error responses carry structured hints**

Some errors now add fields to the `errors` object, next to `message`, `type` and `code`, which do not change. A client that ignores them keeps working.

- `InvalidParam` on a setting the crawler does not have: when another crawler of the same site has it, the message says so ("Unknown parameter: phone. Did you mean functions.get_phone_numbers on Leboncoin Listings & Phone Search Export?") and the response adds `param` and `suggestion`, with the `crawler` id and the `param` to send there. See [Update Squid](/docs/update-squid).
- `TaskNotValidError`: the message shows the value received and the crawler's own example ("The 'url' format is not valid for Facebook Public Group Posts Scraper: got https://www.facebook.com/somepage. Expected something like https://www.facebook.com/groups/211270969394435/"), and the response adds `param` and `example`. See [Add Tasks](/docs/add-tasks).
- `DuplicateSquid`: squid names are unique per account. The message names the squid ("A squid named Reviews already exists.") and the response adds `squid`, the id of the squid that has the name, to reuse it instead of creating it again. See [Create Squid](/docs/create-squid).

```json
{
  "errors": {
    "message": "Unknown parameter: phone. Did you mean functions.get_phone_numbers on Leboncoin Listings & Phone Search Export?",
    "type": "InvalidParam",
    "code": 400,
    "param": "phone",
    "suggestion": { "crawler": "7bc4acdb18f2b90fdd5eb42b8e8251e9", "param": "functions.get_phone_numbers" }
  }
}
```

## Fixed

**Leboncoin Listings & Phone Search Export: no `phone` alias**

The settings page said the old function name `phone` was still accepted. It is not: use `functions.get_phone_numbers`. See [Update Settings](/examples/leboncoin-iter-listings-with-phone/update-settings).
